# producer-java

MVP Java producer for the existing `loan-requests` topic.

- Publishes **Avro + Schema Registry** (`KafkaAvroSerializer`) using the existing schema `io.confluent.banking.LoanRequest` (subject `loan-requests-value`). No JSON path exists.
- Fields: `request_id` (string, random UUID), `customer_id` (int, 1001-1050 = seeded customers), `amount` (decimal(12,2) bytes), `term_months` (int), `purpose` (string), `requested_at` (long, `timestamp-millis`, epoch millis UTC).
- Record key = `String.valueOf(customer_id)` (`StringSerializer`); Flink reads the key as `raw`, so it is compatible.
- The schema is **not duplicated**: `pom.xml` packages `../terraform/schemas/loan-requests.avsc` on the classpath. The build must therefore run with the repository layout intact.
- `auto.register.schemas=false` and `use.latest.version=true`: the producer uses the schema registered by Terraform and never registers an alternative contract.
- Does **not** compute scores, does **not** write `loan-decisions`, does **not** modify infrastructure. Flink is the only decision source.

## Configuration (environment variables)

Names are the ones generated by `scripts/gen-env.sh` in `.env.runtime`:

| Variable | Description |
|---|---|
| `KAFKA_BOOTSTRAP_SERVERS` | Confluent Cloud bootstrap server |
| `PRODUCER_KAFKA_API_KEY` / `PRODUCER_KAFKA_API_SECRET` | Producer Kafka credentials |
| `SCHEMA_REGISTRY_URL` | Schema Registry endpoint |
| `PRODUCER_SR_API_KEY` / `PRODUCER_SR_API_SECRET` | Producer Schema Registry credentials (read-only on `loan-requests-value`) |
| `TOPIC_LOAN_REQUESTS` | Optional, default `loan-requests` |
| `LOAN_CUSTOMER_ID`, `LOAN_AMOUNT`, `LOAN_TERM_MONTHS`, `LOAN_PURPOSE` | Optional. If `LOAN_CUSTOMER_ID` is set, every request is fixed to those values (defaults `10000.00` / `24` / `PERSONAL`); `request_id` and `requested_at` are still generated. Used for single-record checks |
| `DEMO_TRAFFIC`, `DEMO_TRAFFIC_INTERVAL_SECONDS` | Optional. `DEMO_TRAFFIC=true` enables continuous mode (see below); default `false`. Interval: positive integer, default `10` |

Load them from `.env.runtime` (never commit it):

```bash
set -a; source ../.env.runtime; set +a
```

```bash

```

## Run

```bash
java -jar target/loan-request-producer-0.1.0.jar [count=10] [intervalMs=500]
```

## Demo traffic (optional continuous mode)

`DEMO_TRAFFIC=true` publishes 1 random request every `DEMO_TRAFFIC_INTERVAL_SECONDS` (default `10`) until the process receives SIGTERM. Customers `1001`–`1050`, varied `amount`/`term_months`/`purpose`, unique `request_id`, same Avro publication. With `DEMO_TRAFFIC=false` (default) the finite `[count] [intervalMs]` behaviour above is unchanged. Compose service `producer-demo-traffic` (profile `demo-traffic`) is started by `make demo-traffic` and stopped by `make demo-traffic-stop`.

## Compose

Service `producer-java` in `compose/compose.yaml`. It is a finite process (`restart: "no"`) in the `producer` profile, so the default `up -d` (`scripts/local-up.sh`) neither builds nor starts it. Only the 7 variables above are passed explicitly (no `env_file`); it does not depend on Postgres or Connect.

```bash
# from banking-streaming-asset/ (run on demand; not executed yet)
podman compose -f compose/compose.yaml --env-file .env --env-file .env.runtime \
  --profile producer run --rm producer-java 10 500
```

## Container image (UBI)

Multi-stage `Dockerfile`: build on `registry.access.redhat.com/ubi9/openjdk-17`, runtime on `registry.access.redhat.com/ubi9/openjdk-17-runtime` (UBI images pulled without authentication), non-root (UID 185). Secrets are never copied into the image; all configuration comes from the environment variables above at runtime.

The build context must be the asset root (`banking-streaming-asset/`) because the schema is reused from `terraform/schemas/`. `producer-java/Dockerfile.dockerignore` is an allowlist (no `target/`, `.env`, `.env.runtime`).

```bash
# from banking-streaming-asset/ (no registry login required)
podman build -f producer-java/Dockerfile -t loan-request-producer:0.1.0 .
```

- Compose service `producer-java` (profile `producer`): static config PASS.
- **producer-java runtime validation: PASS.** One fixed request (`customer_id=1001`, `amount=10000.00`, `term_months=24`, `purpose=PERSONAL`) published through Compose with the producer's own Kafka and Schema Registry credentials, exit code 0, `KafkaAvroSerializer` with `auto.register.schemas=false` / `use.latest.version=true`. Confirmed in `loan-requests` by a bounded read filtered by `request_id` (exactly 1 row).
- Lesson learned: the Schema Registry property is `basic.auth.credentials.source` (with "s"); the misspelled `credential` was silently ignored and produced a 401.
- Not part of this validation: `loan-decisions` (known latency, ISSUE-1).
